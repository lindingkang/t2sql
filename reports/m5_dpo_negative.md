# M5 DPO 负面结果：被证据钉死的因果链

> **结论前置**：DPO 失败不是"没跑出来"的模糊结论，而是被 bit 级证据钉死的确定性结论。这条路到此为止，不再调 β / lr / 数据配比。

---

## 0. 一句话结论

拒绝采样构造的 DPO 偏好数据产生了**三重过滤**，最后剩下的全是"已被 Step 1 确定性 exec 修复白捡走的简单机械错误"。天花板在造数据那一刻就注定了，与超参无关。修好训练 bug 之后仍然零效果，就是这个结论的直接印证。

---

## 1. 因果链（证据链固化）

每一步都有硬证据，不是口说无凭：

### 证据 A｜bit 级：DPO v2 权重 == SFT 权重
- `dpo_b01_v2/adapter_model.safetensors` 与 SFT adapter `sft_cons_v1` 的 **392 / 392 个 LoRA 张量逐位相同，max 相对偏移 = 0.0**。
- 即 optimizer 一步都没更新参数（训练全程空转）。

### 证据 B｜loss 钉在 ln2、grad_norm = 0
- 256 步训练：`loss` 全程钉在 **0.693 ≈ ln2 = -log σ(0)**（偏好 margin 恒为 0），`grad_norm = 0` 每一步。

### 证据 C｜根因 = 加载顺序 bug（已定位并修复）
- `prepare_model_for_kbit_training` 会无条件 `param.requires_grad = False` 冻结**所有**参数。
- step5 原写法是"先 `PeftModel.from_pretrained` 加 LoRA，再 prepare" → LoRA 被一起冻死 → **0 可训练参数** → grad_norm=0。
- 修复（先 prepare 冻 base，再 PeftModel 加 LoRA）后：可训练参数 0 → **40,370,176**，392/392 LoRA 参数在普通与融合头 forward 的反向里都拿到非零梯度。
- 铁证脚本：`m4/analysis/diag_grad.py`。

### 证据 D｜修复后训练信号正常、但 greedy 评测仍零效果 → 证伪"数据不够"假说
- v3（2047 对，修复后）：`loss` 0.693→0.668、`rewards/accuracies` 0.49→0.87 —— 训练信号强。
- 但 dev 评测 `EA_strict` 只 0.8104 → 0.8114（+1 样本），等于没动。
- **243 对 vs 2047 对结果一致**（0.8104 vs 0.8114）→ "对数太少"假说被证伪。

---

## 2. 为什么修好 bug 仍必败：三层根因

### 根因 1｜偏好对的"选择偏差"（致命伤）

DPO 的 pair **只能从"拒绝采样采到正确答案的题"里构造**：

| 情况 | 结果 |
|---|---|
| 采得到正确答案的题 | 有 pair → 能训练（多是"差一点就对"的机械错误：列名拼错、双引号）|
| 采不到正确答案的题 | 无 pair → 训练不到（恰是 join_type / aggregate / set_op / 语义理解这些硬骨头）|

而 Step 1 的确定性 exec 修复已经把机械错误白捡走了（+25 ER / +15 EA）。所以 **DPO 学的东西，Step 1 已经免费给了——边际收益结构性地等于零**。

数据印证：**359 道错误题 + 2000 做对题采样，只有 808 题成对、1547 题无对**（余 4 道因 gold 执行错跳过）。那 1547 道无对题才是真正的瓶颈，而它们恰恰一个 pair 都没贡献。

### 根因 2｜anchor 对占比过高，稀释有效信号

`step4b_pairs.jsonl` 实际 split：

| 来源 | 对数 | 占比 |
|---|---|---|
| 错误题（359 道）| 589 | ~29% |
| 已做对题（2000 道，anchor）| 1458 | ~71% |

**超过 2/3 的 pair 来自"本来就做对的题"**。这些对教的信号是"偏好 greedy 输出胜过某个坏采样"——模型本来就偏好 greedy，所以这部分梯度信息量 ≈ 0，只起到防遗忘作用（v4b 删掉 anchor 后变差 0.8075，正好证明它只做锚点）。

真正有信号的是错误题那 **589 对**，而它们又全是机械性错误（见根因 1）。

### 根因 3｜DPO 提升了 chosen 概率，但改不动 greedy 路径

- 日志：`rewards/accuracies → 0.87`，`loss 0.693 → 0.668`。模型很快就能区分 chosen/rejected。
- 但 greedy 解码输出纹丝不动。这是 DPO 在可验证任务上的**经典失效模式**：
  - DPO 优化的是**序列级相对概率**；
  - greedy 解码由**逐位置 argmax** 决定；
  - 概率的分布式提升，不一定翻转任何位置的 argmax。
- 这正是在线 RL（GRPO / PPO）在数学/代码任务上系统性优于 DPO 的原因——on-policy 直接优化"实际会生成什么"，而 DPO 优化的是"这两条我更喜欢哪条"。

**一句话总结**：拒绝采样构造 DPO 数据 = 三重过滤，最后剩下的全是"已被 Step 1 解决的简单问题"。

## 3. 天花板审计：还要不要继续？→ 不继续

### 前置问题：这 196 条里有多少是"真错误"？

当前剩 **196 条错误**（Step1 修复后的 dev，分母 1034，口径 EA_strict）：

| failure | 数量 |
|---|---|
| other | 80 |
| join_type | 29 |
| column_order | 28 |
| aggregate | 21 |
| exec_error | 17 |
| set_op | 12 |
| extra_join | 9 |

- `column_order`（28）按口径不计（列序非真错误，已判定不做）。
- "真错误"的准确刻画需要在下一条主线上做 **gold 审计**（哪些是模型错 vs gold 本身噪声：空结果 / 标量多行 / gold 执行错）。
- 但无论 196 里多少是"真"，对 DPO 的结论不变：DPO 够不着这些错误（根因 1/2/3），继续调参无意义。

### 过冲实验（旁证：加力只会更差，不会更好）

| 版本 | 配方 | EA_strict | ER |
|---|---|---|---|
| 基线 | 无 DPO | 0.8104 | 0.9836 |
| v3 全量×原配方(β0.1/lr1e-5/1ep) | **最佳** | 0.8114 | 0.9826 |
| v4b 仅错误×原配方 | 去锚点 | 0.8075 | 0.9826 |
| v4d 仅错误×强配方 | 过冲 | 0.7863 | 0.9778 |
| v4c 全量×强配方(β0.05/lr3e-5/2ep) | **崩** | 0.7340 | 0.9362 |

强配方（β0.05 + lr3e-5 + 2ep）直接把模型打崩：v4c `exec_error 17→66`、ER 掉到 0.9362；v4d 列序暴增到 42。任何"加大力度"都只会更差，进一步坐实"天花板已到"。

## 4. 下一步主线：RFT / STaR round-2（1 天）

### 为什么 RFT 能绕过 DPO 的三个根因

| DPO 的坑 | RFT 怎么绕开 |
|---|---|
| 只训"采得到"的题 | ✅ RFT 只用 chosen、不需要 rejected，**1547 道无对题也能用 gold 补** |
| anchor 稀释信号 | ✅ 不需要构造负样本，全是正样本 |
| 改不动 greedy | ✅ SFT 直接改 token 分布，不依赖偏好对比 |

### 战略价值
Step 1 的 exec 修复是 **test-time 后处理**。RFT round-2 的 chosen 样本天然带正确列名和单引号——等于把 Step 1 **蒸馏进模型**，之后可以（部分）去掉后处理，故事更干净：

> "我用 RFT 把 test-time 的确定性修复内化进了模型。"

### 数据配方

```
RFT round-2 数据 =
    ├─ 原 SFT 数据 ~8.6k（保留，防遗忘）
    ├─ 2047 条 chosen（on-policy 正确样本，权重 ×2）
    └─ 1547 道无对题的 gold SQL（补硬骨头；SFT 可以用 gold！）
```

> 关键口径：DPO 里"严禁用 gold 当 chosen"是对的（对比学习怕分布跳变）；但 **SFT / RFT 用 gold 当目标是完全标准的**——round-1 就是这么做的。

### 训练配置建议

| 项 | 建议 |
|---|---|
| 基座 | 从 base 7B 重新训（**不要**从 SFT adapter 继续叠，易过拟合）|
| LoRA rank | 16 → 32（给更多容量）|
| epoch | 2 → 3 |
| lr | 保持 round-1 的值，别动 |
| 数据 | ~8.6k + 2047(chosen, ×2) + 1547(gold) ≈ 13k |
